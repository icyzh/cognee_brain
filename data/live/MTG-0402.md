Arjun: I want to talk about scale. If the two big merchants we're pitching sign, payments volume goes up five to ten times.
Nora: Is the current setup going to fall over?
Arjun: Maybe not tomorrow, but it's a single primary. We'll hit a write ceiling. I think we should move payments storage to DynamoDB.
Mei: What does that buy us?
Arjun: Throughput. Effectively unlimited writes per second, it scales horizontally, and no database servers for us to babysit.
Nora: How much work is it?
Arjun: The payment API stays the same. Store each payment as an item keyed by payment id, ledger entries next to it. A few sprints.
Mei: Notify only reads the SQS events, so I don't care where payments live.
Nora: Cost?
Arjun: On-demand pricing, so we pay for what we use. Cheaper than over-provisioning for peak.
Nora: I like it for the merchant pitch. "Built for scale" is a good line.
Arjun: I'll write up a proposal to move payments storage to DynamoDB and get a spike going next sprint.
Nora: Do it. Loop in Platform once there's a draft.
